# 11a — Record where traces start: a virtual `Start` node in the structure JSON

**Problem:** report #11 (and part of #10). DPG keeps no record of where traces begin. Every reader
(the equivalence walker, the checker, a person) starts from in-degree-0 nodes. When a tree's root
predicate also appears in the middle of another tree's path, the root gets an incoming edge and stops
being a source. On nursery, 9 of 12 nodes form a cycle with no in-degree-0 entry, so they can never
be reached, although real traces start inside that cycle. The same mechanism made health_insurance's
graph unwalkable (comment in `DROP_COLUMNS_OVERRIDES`: "cyclic with no in_degree-0 nodes -- the route
walker can't start").

**Approach:** count, in `DecisionPredicateGraph.fit`, how many kept traces start at each predicate.
The categorical pipeline then writes a virtual node `START` (label `Start`) into the structure JSON,
with an edge `START → v` weighted by the number of traces starting at `v`. Every transformation,
walker and metric then sees a single, explicit source.

Why a materialised node rather than an attribute (11b): with `START → v` edges, every trace-start
node automatically has an extra parent. The existing degree checks then already do the right
thing everywhere, with no new code in the transformations:
* GROUPED (`_apply_grouping`): `v` is absorbed only if its single parent is `u`, so a start node is
  never absorbed (absorbing it would make traces starting at `v` pass `u`'s test as well).
* SPLIT / CONJUNCTION: a start node has in-degree ≥ 2, so it is cloned for `u`'s branch and the
  original keeps its `START` edge.
* DEDUP (after 6a): a start node has ≥ 2 parents, so it is never restricted by one parent.
* 1b's flow split becomes exact: with the start traffic as an incoming edge, every non-class node
  has `in_w == out_w`.
The DPG core graph (`to_networkx`, node/edge metrics, communities, `DPGExplainer`) is not changed.
Only the categorical pipeline's structure JSON gets the node.

**Depends on:** 14a (traces in true order), 6a (dedup guard), 1b (flow split, if done). Do it late:
it changes BASIC structure JSONs and therefore every metric.

## Changes

### 1. `dpg/core.py`

In `fit`, after `filter_log` and before `discover_dfg`:

```python
# How many kept traces start at each predicate (the tree roots, as reached
# by the traces). A root can also sit in the middle of another tree's path
# and then has incoming edges, so in-degree alone does not identify it.
firsts = log_df.groupby("case:concept:name", sort=False)["concept:name"].first()
self.start_counts = {str(k): int(v) for k, v in firsts.value_counts().items()}
```

Initialise `self.start_counts: Dict[str, int] = {}` in `__init__`, and document the attribute in
the class docstring. `DPGExplainer` keeps the builder as `self._builder`, so the runner reads
`explainer._builder.start_counts` after `explain_global`.

### 2. `categorical/run_all_categorical_experiments.py`

* Constants: `START_NODE_ID = "START"`, `START_LABEL = "Start"` (place them in
  `categorical/cat_grouping.py`, which every pipeline module imports, and import them here).
* `save_dpg_structure_json(..., start_counts=None)`: when given, append
  `{"id": START_NODE_ID, "label": START_LABEL}` to `nodes`, add the node to `graph["nodes"]`, and
  for each `(label, count)` add a link `{"source": START_NODE_ID, "target": node_id(label),
  "weight": float(count)}`, where `node_id` is `DecisionPredicateGraph._label_to_node_id`. Assert
  every target id exists in the graph. Add top-level `"start_node": START_NODE_ID`.
* CLI flag `--no-start-node` (default: the node is written). Log `start_node: true/false` to the W&B
  config.

### 3. Walkers and metrics that pick sources

* `categorical/dpg_equivalence.py`, `predict_with_dpg` and `dpg_routes`: a node whose label is
  `START_LABEL` counts as holding for every row and is the only start when present:
  `holds = True if label == START_LABEL else node_holds_for_sample(label, sample_row)`. `dpg_routes`
  must not put `Start` into `seen_labels` (initialise with `()` instead of `(label,)` for it), so the
  canonical constraints are unchanged. Keep the in-degree-0 rule as the fallback for graphs without
  the node. Update both docstrings.
* `categorical/run_all_metrics.py`:
  * `_real_nodes`: exclude the start node (label `Start`), so `unique_nodes` and `predicate_chars`
    are unchanged;
  * `metric_node_count`: do not count `START_NODE_ID`; `metric_edge_count`: do not count edges
    leaving it. Document both;
  * grep the file for any other walker (`_faithfulness_for_variant` and helpers) and apply the same
    rule if it starts from in-degree-0 nodes.
* `categorical/graph_analysis/analyse_graphs.py` (the checker): in `path_cons` and in the node-level
  checks, skip nodes labelled `Start` (they constrain nothing). `enumerate_paths` needs no change:
  `START` is then the only in-degree-0 node. Also `categorical/graph_diagnostics.py` (10a) if it
  exists.
* `categorical/graph_analysis/check_views.py` (0a): exclude `START` from `graph_nodes` and its edges
  from `edges`, and report `has_start_node`.
* `categorical/graph_analysis/render_side_by_side.py` and the `_build_dot*` functions: draw the start
  node as a small black dot (`shape="point"`) so it does not look like a predicate. Optional. If you
  do it, do it in all five renderers consistently.

### 4. Stress-test harness

`latent_reachability.dfg_to_structure(dfg, start_counts=None)`: add the same `START` node and edges
(compute `start_counts` from `flog` with the same `groupby(...).first()` in `run_one`). Do not change
any probe.

## Tests

1. `tests/test_dpg_core.py` (new test): after `fit` on the iris fixture, `sum(start_counts.values())`
   equals the number of kept traces (rows × trees when `perc_var` keeps everything), and every key is a
   node label of the graph.
2. `tests/categorical/test_start_node.py`:
   * GROUPED: `u: "X_p <= 0.5" → v: "X_q <= 0.5" → k`, plus `START → u 5`, `START → v 3`, `u→v 5`,
     `v→k 8`. `v` must **not** be absorbed (traces starting at `v` never tested `u`). Without the
     `START → v` edge it is absorbed.
   * CONJUNCTION on the same input: `v` keeps its id and label; a clone carries `u`'s branch; total
     weight into `k` equals 8 (needs 1b).
   * `dpg_equivalence.predict_with_dpg` on a 2-node cycle reachable only through `START` (labels
     `X_a <= 0.5 ↔ Y_b <= 0.5`, `Y_b <= 0.5 → Class 1`, `START → X_a <= 0.5`) returns `"1"` for a row
     with `X_a = 0, Y_b = 0`; without `START` it returns `None` (documents the bug).
   * `run_all_metrics.metric_node_count` and `_real_nodes` ignore the start node.
