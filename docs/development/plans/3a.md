# 3a — Intersect `IN` sets, keep contradictions visible

**Problem:** report #3. `X IN {a}` followed by `X IN {b}` means `X = a AND X = b` (impossible),
but every merge site writes `X IN {a, b}` (either). An impossible rule turns into a valid-looking
one. Only `NOT IN` sets may be unioned. The metric (`dpg_equivalence.canonical_constraints`, step 2)
makes the same mistake, so it cannot detect the bug.
**Approach:** one small shared module with the correct set algebra:

* `NOT IN` ∧ `NOT IN` → `NOT IN` (union) — unchanged;
* `IN` ∧ `IN` → `IN` (intersection);
* if the intersection is empty, the clauses are a contradiction: **do not merge them**, keep both
  clauses as they were so the contradiction stays visible.

In GROUPED and SPLIT an `IN → IN` same-feature edge cannot come from a real DPG (report F2(a)), so
there the fix is simply "never merge two `IN` nodes". In CONJUNCTION it does happen (stress test:
32,479 wrong merges in 66 of 911 graphs, always from contradictory input).
**Depends on:** 0a. **Followed by:** 4a (opposite operators), which edits the same function.

## Changes

### 1. New module `categorical/clause_algebra.py`

```python
"""Set algebra for conjunctions of ``base IN {..}`` / ``base NOT IN {..}`` clauses.

Two clauses on the same base, both true on a path:

* ``NOT IN {a}`` and ``NOT IN {b}``  ->  ``NOT IN {a, b}``   (union of the excluded values)
* ``IN {a, b}``  and ``IN {b, c}``   ->  ``IN {b}``          (intersection of the allowed values)

An empty intersection means no row can satisfy both clauses. The helpers
then return ``None`` and the caller keeps the original clauses, so the
contradiction stays visible instead of turning into a valid-looking rule.
"""
from __future__ import annotations

from typing import List, Optional, Sequence


def dedup(values: Sequence[str]) -> List[str]:
    """``values`` without repeats, first-seen order kept (labels stay stable)."""
    seen, out = set(), []
    for v in values:
        if v not in seen:
            seen.add(v)
            out.append(v)
    return out


def merge_same_op(op: str, first: Sequence[str], second: Sequence[str]) -> Optional[List[str]]:
    """Categories of ``base <op> {first} AND base <op> {second}`` as one clause,
    or ``None`` when ``op`` is ``IN`` and the sets are disjoint (contradiction)."""
    if op == "NOT IN":
        return dedup(list(first) + list(second))
    keep = set(second)
    merged = [c for c in dedup(first) if c in keep]
    return merged or None
```

Import form: `cat_duplicate_split_peer.py` imports `cat_grouping` as a top-level module
(`from cat_grouping import ...`) while the runners import `categorical.cat_grouping`. Every module
that imports `clause_algebra` must therefore use

```python
try:
    from .clause_algebra import merge_same_op
except ImportError:  # imported as a top-level module (categorical/ on sys.path)
    from clause_algebra import merge_same_op
```

## Tests — `tests/categorical/test_clause_algebra.py`

Report example (`X_a > 0.5 -> X_b > 0.5 -> Class 1`, no row can follow it):

1. GROUPED: labels after `_apply_grouping` keep `X IN {a}` and `X IN {b}` as two nodes; nothing is
   collapsed.
2. SPLIT: `_split_then_merge` returns both nodes unchanged.
3. CONJUNCTION: the result contains no label with `X IN {a, b}`; the merged node's label contains
   both `X IN {a}` and `X IN {b}`.
4. `merge_same_op("IN", ["a", "b"], ["b", "c"]) == ["b"]`; `merge_same_op("IN", ["a"], ["b"]) is None`;
   `merge_same_op("NOT IN", ["a"], ["b", "a"]) == ["a", "b"]`.
5. `_combine_clauses([("X","IN",["a","b"])], [("X","IN",["b","c"])]) == [("X","IN",["b"])]`;
   `_combine_clauses([("X","IN",["a"])], [("X","IN",["b"])]) == [("X","IN",["a"]), ("X","IN",["b"])]`.
6. `_simplify_same_base([("X","IN",["a"]), ("Y","NOT IN",["p"]), ("X","IN",["b"])])` keeps both
   `X` clauses; with `["a","b"]` and `["b"]` it returns one `("X","IN",["b"])`.
7. `NOT IN` behaviour unchanged: `_simplify_same_base([("X","NOT IN",["a"]), ("X","NOT IN",["b"])])
   == [("X","NOT IN",["a","b"])]`.
8. `canonical_constraints(["X IN {a}", "X IN {b}"])` contains `("cat","X","IN",frozenset())`;
   `canonical_constraints(["X NOT IN {a}", "X NOT IN {b}"])` contains
   `("cat","X","NOT IN",frozenset({"a","b"}))`.
