# 11b — `start_nodes` attribute with guards everywhere (alternative, not recommended)

**Problem:** report #11 (see 11a).
**Approach:** record the trace-start counts (same `DecisionPredicateGraph.start_counts` as 11a,
step 1), but store them as an attribute, `"start_nodes": {node_id: count}`, in the structure JSON
instead of materialising a `START` node. Then teach every consumer about it.
**Status:** not recommended. A start node behaves like a node with one extra, invisible parent.
11a makes that parent explicit, and the existing degree checks protect it for free. 11b needs a
dedicated guard in each transformation, and any future transformation that forgets the guard
silently changes the meaning of traces that start at an absorbed node. Weights also stay
approximate in 1b's flow split (start traffic has no incoming edge). Choose 11b only if a visible
extra node in the JSON is unacceptable to the user.

## Changes (if chosen)

1. `dpg/core.py`: as 11a step 1.
2. Runner: `save_dpg_structure_json(..., start_counts)` writes
   `"start_nodes": {node_id(label): count}`. The views inherit the key through `dict(structure)`.
   Clone ids never become start nodes.
3. Guards (each one must cite report #11 in a comment):
   * `cat_grouping._apply_grouping._mergeable(u, v)`: `False` if `v` is a start node;
   * `cat_grouping_split._split_then_merge` and `cat_grouping_split_conjunction._split_then_merge`:
     settle `(u, v)` if `_original_id(v)` (8a) is a start node. Unlike 11a, this forbids even the
     clone-based merge for `u`'s branch. That is conservative but simple;
   * `cat_duplicate_split_peer._deduplicate_labels`: skip `v` if it is a start node, and never drop it.
4. Walkers (`dpg_equivalence.predict_with_dpg`, `dpg_routes`), `analyse_graphs.enumerate_paths`,
   `graph_diagnostics` (10a): sources = start nodes ∪ in-degree-0 nodes.

## Tests and validation

Same as 11a, except: no node-count adjustments in the metrics. The flow-violation check
(`check_views`) cannot reach 0 for BASIC (start traffic is invisible), so compare against the
baseline instead. Add a test per guard (one per transformation) showing that a start node is not
absorbed.
