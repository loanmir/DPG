# 16a — `fit` with `n_jobs: 1` (and the parallel fallback) must not crash

**Problem:** report #16. In `DecisionPredicateGraph.fit` (`dpg/core.py`), the parallel path returns
a list of per-chunk lists of `[case, event]` pairs, and the shared line
`log = [item for sublist in log for item in sublist]` flattens it once into pairs. The sequential
path (`if self.n_jobs == 1:`) already builds a flat list of pairs, so the shared line flattens it a
second time into bare strings, and `pd.DataFrame(log, columns=[...])` raises
`ValueError: Shape of passed values is (N, 1), indices imply (N, 2)`. The **fallback** used when the
parallel path fails (`except Exception as _exc:` branch) builds the log the same way and crashes
too, so a joblib failure is fatal instead of "slower, but correct", as the comment promises.
`n_jobs: 1` is the obvious setting to save RAM on large datasets (rain_australia ran out of memory
with the parallel path).
**Approach:** make both sequential branches produce one list per sample, i.e. the same nesting as
the parallel branch, so the shared flatten is correct for all three.
**Depends on:** 0a.

## Changes

`dpg/core.py`, `fit`. Both sequential constructions:

```python
log = [
    item
    for sublist in (
        self.tracing_ensemble(i, sample)
        for i, sample in enumerate(X_arr)
    )
    for item in sublist
]
```

become

```python
# One list of [prefix, event] pairs per sample -- the same nesting as the
# parallel branch's per-chunk lists, flattened once below.
log = [list(self.tracing_ensemble(i, sample)) for i, sample in enumerate(X_arr)]
```

(Factor this into a small local helper used by both branches, to avoid the duplication that caused
the bug.) Do not change the parallel branch or the shared flatten line.

Also check the class docstring and `config.yaml` comments: if anything says `n_jobs: 1` is
unsupported, update it.
