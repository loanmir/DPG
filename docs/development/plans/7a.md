# 7a — Store the real one-hot map and stop guessing with `rsplit("_", 1)`

**Problem:** report #7. `_split_one_hot_column` guesses the original column of a one-hot dummy by
splitting at the last `_`, and treats any `name_word` column tested at 0.5 as a dummy:

```text
_split_one_hot_column('job_self_employed') -> ('job_self', 'employed')   true: ('job', 'self_employed')
_split_one_hot_column('has_loan')          -> ('has', 'loan')            true: numeric column 'has_loan'
```

Affected in the local datasets: numeric `Maintenance_Hours` (accidents_mining), `person_emp_exp`
(credit_card_approval/_visual), `Region_Code`, `Driving_License`, `Previously_Insured`
(health_insurance); one-hot `MTRANS_Public_Transportation` (obesity_levels_uci); `children_1/2/3`
(nursery, numeric-looking category). The pipeline graphs avoid them by luck. On other seeds the
labels are wrong and numeric tests get merged as categories.
**Approach:** the true mapping is known when the features are encoded (`pd.get_dummies`). Compute
it there, store it in the BASIC structure JSON as `onehot_map`, let every view carry it, and make
every label rewrite and the equivalence metric use it. The old guess remains only as a fallback for
JSONs that lack the map (with a warning).
**Depends on:** 2a (creates `categorical/onehot.py`). Do it after the 3a–6a chain, because it
touches `cat_grouping.py` helpers those plans import.

## Changes

### 1. `categorical/onehot.py` (extend 2a's module)

```python
def build_onehot_map(features: pd.DataFrame) -> Dict[str, Tuple[str, str]]:
    """``{dummy column: (original column, category)}`` for every column that
    ``pd.get_dummies(features, drop_first=False)`` creates. The original column
    is known here, so the split never has to be guessed from the name."""
```

Implementation:

* for each `col` in `categorical_columns(features)`: `dummies = pd.get_dummies(features[[col]],
  drop_first=False).columns`; each dummy starts with `f"{col}_"` (assert it); the category is the
  rest of the name. Using `get_dummies` itself (not `f"{col}_{value}"`) guarantees the same spelling
  as the training columns, including how non-string values are printed.
* raise `ValueError` if two (column, category) pairs give the same dummy name, or if a dummy name
  equals a numeric column name;
* warn (print `[warn] ...`, do not fail) when a category contains `,`, `{` or `}`. The
  `base IN {a, b}` label grammar cannot represent those values.

```python
def split_one_hot_column(col: str, onehot_map: Optional[Mapping[str, Sequence[str]]] = None
                         ) -> Optional[Tuple[str, str]]:
    """``(original column, category)`` of a one-hot dummy, ``None`` for a numeric column.
    Uses ``onehot_map`` when given; otherwise falls back to the legacy guess
    (split at the last ``_``, numeric last token = not one-hot)."""
```

Move the body of today's `cat_grouping._split_one_hot_column` into a private `_guess_split(col)`
in this module for the fallback. JSON stores the map values as 2-element lists, so convert with
`tuple(...)`.

### 2. `categorical/run_all_categorical_experiments.py`

## Tests — `tests/categorical/test_onehot.py` (extend)

1. `build_onehot_map` on a frame with `job` ∈ {`self_employed`, `admin`}, numeric `has_loan` ∈ {0, 1},
   `children` ∈ {`1`, `2`, `more`} (object column), numeric `Maintenance_Hours` ∈ 0..9:
   `{"job_self_employed": ("job","self_employed"), "job_admin": ("job","admin"),
   "children_1": ("children","1"), "children_2": ("children","2"), "children_more": ("children","more")}`.
2. `split_one_hot_column` with that map: `job_self_employed` → `("job","self_employed")`;
   `has_loan` → `None`; `Maintenance_Hours` → `None`; `children_1` → `("children","1")`. Without a map:
   the legacy results (`("job_self","employed")`, `("has","loan")`, `None` for `children_1`).
3. Collision: columns `a_b` with value `c` and `a` with value `b_c` → `ValueError`.
4. `cat_grouping._build_label_map` on a structure with `onehot_map` and labels
   `has_loan > 0.5`, `job_self_employed <= 0.5`, `MTRANS_Public_Transportation > 0.5`
   (map `MTRANS_Public_Transportation → ("MTRANS","Public_Transportation")`):
   `has_loan > 0.5` unchanged, `job NOT IN {self_employed}`, `MTRANS IN {Public_Transportation}`.
5. Conjunction view on `Maintenance_Hours > 0.5 -> Weather_Fog > 0.5 -> Class 1` with the map: the
   numeric node is not merged (label `Maintenance_Hours > 0.5` stays a separate node).
6. `dpg_equivalence.canonical_constraints(["has_loan > 0.5"], onehot_map={...})` yields a `("num", ...)`
   constraint, not a `("cat", ...)` one.
