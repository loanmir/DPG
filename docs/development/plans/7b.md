# 7b — Unambiguous one-hot separator (alternative, not recommended)

**Problem:** report #7 (see 7a).
**Approach:** encode with a separator that cannot appear in column names, e.g.
`pd.get_dummies(features, drop_first=False, prefix_sep="=")`. A dummy is then `job=self_employed`,
and splitting at the **first** `=` is unambiguous. A numeric column never contains `=`, so it is never
mistaken for a dummy.
**Status:** not recommended. It changes every BASIC label of every categorical dataset
(`job_admin > 0.5` → `job=admin > 0.5`), so all stored graphs, W&B runs, figures and the report's
examples become incomparable, and external users with existing graphs gain nothing. 7a fixes the
same problem without changing a single label. Choose 7b only if the user explicitly prefers
self-describing labels over a stored map.

## Changes (if chosen)

1. `run_all_categorical_experiments.load_dataset`, `dpg_equivalence.load_eval_rows` and
   `analyse_graphs.load_domain`: add `prefix_sep="="` to every `pd.get_dummies` call (grep the repo
   for `get_dummies(`; all calls that feed the categorical pipeline must agree).
2. `cat_grouping._split_one_hot_column`, `categorical_view_conversion._split_one_hot_column`,
   `dpg_equivalence._split_one_hot_column`: split with `col.split("=", 1)`; return `None` when there
   is no `=`.
3. `_PREDICATE_PATTERN` in `cat_grouping.py` and `categorical_view_conversion.py`: check that
   `(?P<feature>.+?)` still matches `job=admin <= 0.5` (it does, `.+?` is lazy up to the operator),
   and that no regex treats `=` in the feature part as the `==` operator. Add a test.
4. Fail loudly (`ValueError` in `load_dataset`) if any original column name contains `=`.

## Tests

`job=self_employed > 0.5` → `job IN {self_employed}`; `has_loan > 0.5` unchanged; `children=1 <= 0.5`
→ `children NOT IN {1}`; a column name containing `=` raises.

## Validation

Regenerate everything (`--no-wandb`), run `analyse_graphs` (it uses its own `load_domain`, updated in
step 1) and the mini grid. Acceptance: `n_changed_paths == 0`, `item7_*` not reached. Graphs
differ from the baseline only in label spelling. Check it: replacing `=` by `_` in every BASIC label
of the new run gives the baseline's labels, on all 11 datasets.
