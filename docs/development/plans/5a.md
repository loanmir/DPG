# 5a — Dedup restriction for parent `IN` / child `NOT IN`: keep `c ∩ p`

**Problem:** report #5. `cat_duplicate_split_peer._restrict_clause`, case parent `X IN {p}`,
child `X NOT IN {c}`: the code (and the docstring) keeps `c \ p`. Under the parent only values of
`p` can arrive, so the values of the exclusion that still matter are `c ∩ p`. On every satisfiable
path both forms mean the same (the report proves it), so the fix only matters for keeping
impossible rules visible. It is a two-line change, so it is worth doing for correctness.
**Depends on:** 0a. Do it before 6a (same file).

## Changes

`categorical/cat_duplicate_split_peer.py`:

1. `_restrict_clause`, branch `if op_p == "IN" and op_c == "NOT IN":`

   ```python
   # Only values of cats_p reach the child, so of the child's exclusion
   # only (cats_c ∩ cats_p) still matters. An empty result means the
   # exclusion is always true here and the caller drops the clause.
   new_cats = [c for c in cats_c if c in cats_p_set]
   return (base_c, "NOT IN", new_cats)
   ```

2. Module docstring, the block

   ```text
   P = ``base IN {p}``  and  Ci = ``base NOT IN {c}``
       ->  Ci becomes ``base NOT IN {c \\ p}``
       (combined: base must be in p AND not in c, ...
   ```

   → `Ci becomes base NOT IN {c ∩ p}`, with the explanation: rows reaching the child have
   `base ∈ p`, so excluding values outside `p` is redundant; excluding values inside `p` is the part
   that still filters. If `c ∩ p` is empty the clause is always true and is dropped. If `c ∩ p = p`
   the child can never be reached (contradiction) and the clause stays visible.

No caller change is needed: an empty `NOT IN` result is already dropped as "trivially true" by
`_deduplicate_labels`.

   `c ∩ p` is empty and the clause is dropped.)
