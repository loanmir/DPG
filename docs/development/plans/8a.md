# 8a — Never merge into a node whose original id lies in a cycle

**Problem:** report #8, second half: on other seeds the CONJUNCTION pass runs until its iteration
cap, `10 × (edges + labels + 10)`, and returns a graph 12–75× larger than BASIC (146 of 911
stress-test graphs; the pipeline's own seed and tree count at `perc_var` 0.005 already hit it:
accidents_mining 34 → 1,386 nodes, adult_subset 52 → 1,628). The report left the cause open.

**Cause (found while writing this plan).** The conjunction script excludes every edge whose two
endpoints lie in the same strongly connected component (SCC). The exclusion is computed **once, on
the original node ids**. A merge along an edge that *enters* a cycle from outside is still allowed.
`u` (outside the cycle) absorbs a clone of the cycle node `v` and inherits `v`'s outgoing edges,
which point to further cycle nodes. Those edges have a clone id or a new source (`u`), are not in
the excluded set, and are merged too. `u` walks around the cycle indefinitely, creating one clone
per step. Measured on accidents_mining (seed 27, 10 trees, `perc_var` 0.005, true trace order):
BASIC has 34 nodes and one 24-node SCC; the categorical part outside the SCC has only 8 edges, but
the pass creates 1,352 clones, **1,207 of them copies of SCC members**, and ends at the cap.

**Approach:** settle (never merge) any edge `u → v` whose target's **original** id (the id with
every `#<n>` clone suffix removed) belongs to a non-trivial SCC of the input graph. Merges out of a
cycle (`u` in the cycle, `v` outside) stay allowed; they terminate, because `v` and its successors
are outside the cycle.

**Evidence.** A patched copy of the script with exactly this guard (scratch test, not committed):

| case | BASIC | CONJ before | CONJ with guard |
|---|---|---|---|
| accidents_mining seed 27, 10 trees, 0.005 | 34 | 1,386 (cap) | 37 |
| adult_subset seed 27, 10 trees, 0.005 | 52 | 1,628 (cap) | 52 |
| bank_marketing seed 3, 5 trees, 0.005 | 145 | 4,073 (cap; report, repo-DPG build) | 144 |
| bank_marketing seed 27, 10 trees, 0.001 | 424 | not measured | 426 |

All finished in under 0.1 s. The same guard in the split script fixes #15 (plan 15a).

**Depends on:** 0a. Do it before 1a/1b (same functions). Plan 15a reuses the helpers added here.

## Changes

### 1. Helpers in `categorical/cat_grouping.py` (shared by the split and conjunction scripts)

```python
def _original_id(node_id: str) -> str:
    """Id of the BASIC node a (possibly cloned) node comes from: clones are
    named ``<id>#<n>`` and clones of clones ``<id>#<n>#<m>``."""
    return node_id.split("#", 1)[0]


def _cycle_node_ids(nx_graph) -> Set[str]:
    """Ids of the nodes that lie on a cycle of ``nx_graph`` (members of a
    strongly connected component with more than one node)."""
    return {
        str(n)
        for component in nx.strongly_connected_components(nx_graph)
        if len(component) > 1
        for n in component
    }
```

(`import networkx as nx` at the top of `cat_grouping.py`.) A one-node SCC with a self-loop cannot
occur: a self-loop `a → a` would need a tree to test the same predicate twice in a row, which
scikit-learn never does (report F2).

### 2. `categorical/cat_grouping_split_conjunction.py`, `_split_then_merge`

* Replace the block that builds `scc_id` / `scc_size` and pre-settles the intra-SCC edges with
  `cycle_nodes = _cycle_node_ids(nx_graph)` (import both helpers from `cat_grouping` like the other
  helpers).
* In the candidate loop, after the `if u not in clauses or v not in clauses:` check, add:

  ```python
  if _original_id(v) in cycle_nodes:
      # Merging into a cycle node lets u inherit edges that lead around
      # the cycle; the clones they produce are not in the cycle-node set
      # under their new ids, so the walk never ends (report #8).
      settled.add((u, v))
      continue
  ```

  This also covers every edge with both endpoints in a cycle, so the old pre-settling is not needed.
* Module docstring, paragraph "Dropping the same-feature restriction has one sharp edge ...": the
  rule is now "never merge into a node that lies on a cycle (identified by its original id, so clones
  of cycle nodes count too)". Explain in one sentence why the old intra-SCC rule was not enough.

### 3. Report the outcome of the pass instead of failing silently

Today, hitting the cap only prints a warning and returns whatever state the loop reached. Without
changing the `(labels, edges)` return value:

* add a module-level dict `LAST_RUN_STATS: Dict[str, object] = {}` to the conjunction module
  (and later 15a does the same for the split module). At the end of `_split_then_merge` set
  `LAST_RUN_STATS.clear(); LAST_RUN_STATS.update(capped=<bool>, iterations=<int>,
  clones=clone_counter, max_iterations=max_iterations)`. Use `for/else` as now; count iterations
  with `enumerate`.
* in `_process_subdir` (conjunction module), after `_split_then_merge`, add
  `split_structure["grouping_status"] = dict(LAST_RUN_STATS)` before dumping the JSON.
* `run_all_categorical_experiments.run_one_dataset`: after each grouping module ran, if the module
  has `LAST_RUN_STATS` and `capped` is True, print `[warn] <module> hit its iteration cap on <dataset>`.
  Also add `"conj_capped": <bool>` to the dict the function returns, and log it to W&B wherever the
  other per-dataset values (`n_nodes`, `n_edges`, ...) are logged.
