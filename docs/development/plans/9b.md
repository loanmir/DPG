# 9b — Optional per-class `perc_var` filter

**Problem:** report #9. `DecisionPredicateGraph.filter_log` keeps a path variant only if it is
followed by at least `perc_var × (number of traces)` traces. On imbalanced data no variant ending in
a minority class reaches that bar, so the class disappears from the graph.
**Approach:** an opt-in mode `perc_var_mode: per_class`: a variant ending in class `c` is kept if it
is followed by at least `perc_var × (number of traces ending in class c)` traces. The default stays
`global`, so existing graphs and tests do not change.
**Status:** optional, and a methodological change (it alters what a DPG is). Run it only if the user
asks. It is measured here, never made the default in this plan.
**Depends on:** 9a (to measure coverage) and 14a (so the graphs built for the comparison are not
scrambled).

## Changes

1. `dpg/core.py`:
   * `DEFAULT_DPG_CONFIG["dpg"]["default"]["perc_var_mode"] = "global"`;
   * `__init__`: `self.perc_var_mode = default_config.get("perc_var_mode", "global")`; raise
     `DPGError` for anything other than `"global"` / `"per_class"`; include it in the
     `DPG initialized with ...` print.
   * `filter_log`:

     ```python
     variant_map = defaultdict(list)
     for case_id, group in log.groupby("case:concept:name", sort=False):
         variant = "|".join(group["concept:name"].values)
         variant_map[variant].append(case_id)

     n_cases = len(log["case:concept:name"].unique())
     if self.perc_var_mode == "per_class":
         # The last event of a trace is its leaf ("Class X" / "Pred v"):
         # each leaf value gets its own frequency bar.
         per_leaf = Counter()
         for variant, case_ids in variant_map.items():
             per_leaf[variant.rsplit("|", 1)[-1]] += len(case_ids)
         min_count = {v: per_leaf[v.rsplit("|", 1)[-1]] * self.perc_var for v in variant_map}
     else:
         min_count = dict.fromkeys(variant_map, n_cases * self.perc_var)
     ```

     (`filter_log` already imports `defaultdict` locally; import `Counter` next to it), then keep
     the `case_ids` of variants with `len(case_ids) >= min_count[variant]`. Careful: an event
     label can contain `|` in theory; if any label in the log contains `|`, fall back to grouping by
     the last row of each group instead of `rsplit`. Simplest robust version: record the last event
     while building `variant_map` (`group["concept:name"].values[-1]`) in a second dict.
     For regressors (`Pred v` leaves) per-leaf thresholds make little sense: if the model is a
     regressor and the mode is `per_class`, raise `DPGError`.
   * Update the `filter_log` docstring.
2. `config.yaml`: add `perc_var_mode: global` under `dpg.default` with a one-line comment.
3. `categorical/run_all_categorical_experiments.py`: CLI option `--perc-var-mode {global,per_class}`
   (default: take it from the config). `resolve_config_path` writes it into the staged config copy
   when given. Log it to the W&B config.

## Tests — `tests/test_dpg_core.py` (new test class) or a new `tests/test_filter_log.py`

Build a `DecisionPredicateGraph` around any fitted small forest (reuse an existing fixture) and call
`filter_log` directly on a hand-made log `DataFrame` with columns `case:concept:name`, `concept:name`:
100 traces of variant `A|Class x`, 5 traces of variant `B|Class y`, `perc_var = 0.1`. `global` keeps
only the `Class x` traces (bar 10.5); `per_class` keeps both (bars 10 and 0.5). An unknown mode
raises `DPGError`. The existing exact-count tests (`test_exact_node_count` etc.) must still pass.
