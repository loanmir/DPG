# 14a — Stop `discover_dfg` from scrambling long traces

**Problem:** report #14. `DecisionPredicateGraph.discover_dfg` (`dpg/core.py`) re-sorts each trace
by its case id before counting consecutive pairs:

```python
trace_df = trace_df.sort_values(by="case:concept:name")
```

The key is constant within a trace, so the sort should do nothing. But pandas' default `quicksort`
is not stable. numpy's introsort keeps equal keys in order only for 16 items or fewer, so every
trace of 17+ events (16+ tests plus the class) is permuted:
`[0, 14, 13, 12, 11, 10, 9, 15, 8, 6, 5, 4, 3, 2, 1, 7, 16]`. The root and the class stay in place, so
the broken graph looks plausible. On the pipeline's bank_marketing graph, all 16 edges of the
dominant rule (504 of 1,102 traces) are wrong. With the true order, the graph has 4 paths instead
of 8 and 1 path with a redundant test instead of 5.
**Approach:** delete the sort. `log.groupby("case:concept:name", sort=False)` already yields each
trace's rows in log order, which is the order `fit` appended the events in.
**Depends on:** 0a. This changes BASIC graphs that contain traces of 17+ events, so every view and
metric downstream must be regenerated (R1).

## Changes

`dpg/core.py`, `discover_dfg`: remove the line `trace_df = trace_df.sort_values(by="case:concept:name")`
and add a comment where it was:

```python
# ``groupby`` keeps each trace's rows in log order, i.e. the order the
# tests were applied. Do not sort here: the key is constant within a
# trace and pandas' default sort is not stable, so a sort would permute
# traces longer than 16 events.
```

`filter_log` builds variants with the same `groupby(..., sort=False)` and no sort, so it needs no
change. Check that no other function in `dpg/` sorts a trace (`grep -n "sort_values" dpg/*.py`); fix
any other instance the same way and list it in the execution log.

`categorical/graph_analysis/latent_reachability.py` keeps `true_order_dfg` (it is now equivalent to
`discover_dfg`). Do not remove it. Its `edges_only_in_dpg` counter is the regression check below.
