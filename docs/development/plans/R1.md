# R1 — Regenerate everything, re-validate, update the report and W&B

**Problem:** none of its own. After the chosen plans are merged, every stored graph, figure, metric
and W&B table describes the old code. This plan produces revision 3 of
`docs/development/graph_analysis_report.md` from the fixed pipeline.
**Depends on:** every plan the user chose to execute (at least the "recommended" ones in the README
table). Run it once, at the end.

## Steps

### 1. Preconditions

* Every executed plan has an `## Execution log` with all its acceptance criteria met. List the
  executed plans and their commits; note which optional plans were skipped.
* `PYTHONPATH=. .venv/bin/python -m pytest -q tests/` passes.
* `git status` clean on `fix/graph-analysis-plans`.

### 2. Regenerate the pipeline outputs locally (no W&B yet)

```bash
.venv/bin/python categorical/run_all_categorical_experiments.py --no-wandb --datasets $DS
mkdir -p outputs/plans_scratch/R1
.venv/bin/python categorical/graph_analysis/check_views.py outputs/categorical outputs/plans_scratch/R1/check_views.json $DS
DPG_OUTPUTS_ROOT=outputs/categorical .venv/bin/python categorical/graph_analysis/analyse_graphs.py outputs/plans_scratch/R1 $DS
```

(`$DS` explicitly includes `credit_card_visual` so the report can still show it was a duplicate. Drop
it here if the user chose 12b.)

Acceptance (summary of the plans' criteria, now all at once):

| check | expected |
|---|---|
| `analyse_graphs` `n_changed_paths` | 0 for every view of every dataset |
| `class_inflow_ratio` | 1.00 for every view (1a + 1b) |
| orphans | 0 in every view (13a) |

| nursery | 0 unreachable nodes, more than 1 path (11a, if executed) |
| BASIC `flow_violations` | 0 everywhere (11a, if executed) |

If any check fails, stop. Find the plan whose criterion it was and report it to the user.

### 3. Figures

```bash

```

The renderer marks edges whose weight differs from BASIC in red. After 1a/1b only clone splits
should differ. Look at three figures (accidents_mining, adult_subset, nursery) and describe in the
execution log what changed visually.

### 4. Stress test (full grid)

Time the mini grid (`bash categorical/graph_analysis/mini_grid.sh outputs/plans_scratch/R1/mini_grid`,
16 jobs) and extrapolate to the full grid's 330 jobs (`outputs/latent_reachability/jobs.txt`). The
revision-2 grid took about an hour on 6 cores, mostly in the runaway cases that 8a/15a remove.

* If the estimate is **under one hour**: run the grid locally, as in the report's "Reproducing"
  section, into `outputs/plans_scratch/R1/grid/` with `VIEW_TIME_LIMIT=600`, then
  `latent_reachability.py summary`.
* Otherwise: **stop and ask the user** whether to offload to malelab2023. If yes, follow
  `/root/gitgud/.github/instructions/malelab-compute.instructions.md` exactly (CPU budget below 75 %,
  rsync push of the repo without `.venv`/`outputs`, tmux session `gg-dpg-grid`, pull back only the
  `.jsonl` files and `summary.txt`).

Acceptance: no `wrong from SAT` anywhere; `wrong from UNSAT` zero for the `item3_*`, `item4_*` and
`dedup_*` branches; no `*_iteration_cap` or `*_timeout`; `edges_only_in_dpg` zero; `item7_*` not
reached. Record the summary tables for the report.

### 6. Update the report

Edit `docs/development/graph_analysis_report.md` into **revision 3**. Keep revision 2's structure
and history; do not delete problem sections.

* Header: date, pipeline commit, "revision 3".
* New section "What changed in revision 3" at the top (above "What changed in revision 2"): one
  bullet per executed plan, in plain words, with its commit.
* Summary table: change the **Status** of every fixed problem to "**fixed** (plan Na, `<commit>`)",
  and of measured-only problems (#9, #10) to "**measured**". Keep the "Solution (plans)" column.
* Problem sections: under each fixed problem, add a short "**Fixed in revision 3**" paragraph with
  the before/after numbers from the validation (e.g. #1: ratios now 1.00; #8: accidents_mining
  34 → 37 instead of 1,386; #14: bank_marketing 4 paths instead of 8). Do not rewrite the original
  analysis.
* Problems in the original graphs table: add a revision-3 column or a second table (bank_marketing
  changes with 14a, nursery with 11a).
* Stress-test section: add the revision-3 summary next to revision 2's.
* Reproducing section: add `check_views.py`, `mini_grid.sh`, `DPG_OUTPUTS_ROOT`, and the new CLI flags
  that the executed plans added.
* Figures: regenerated in step 3. Update the captions where the numbers changed.

Follow the report's existing style (plain sentences, numbers with their unit, no marketing words).
No AI attribution anywhere.
