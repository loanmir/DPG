# 9a — Report class coverage next to every metric

**Problem:** report #9. 7 of the 11 BASIC graphs have no node for at least one class (nursery 1 of
5, obesity 2 of 7, five binary datasets only the majority class). These graphs cannot explain a
prediction of a missing class, and every metric computed on them covers only the classes present.
Nothing in the metrics tables shows this today.
**Approach:** measure it. Add class-coverage columns to the metrics tables and to the experiment
run summary. Changing the filter so that more classes survive is 9b (optional).
**Depends on:** 0a.

## Changes

1. `categorical/run_all_metrics.py`:
   * new metric functions next to the others:

     ```python
     def metric_classes_covered(structure: dict) -> int:
         """Number of distinct ``Class X`` nodes in the graph."""

     def metric_classes_total(structure: dict) -> int:
         """Number of classes of the dataset (``target_names`` in the structure JSON)."""

     def metric_missing_classes(structure: dict) -> str:
         """Comma-separated target names with no ``Class X`` node ("" when none)."""
     ```

     Use `_real_nodes(structure)` for the labels. `target_names` is written by
     `save_dpg_structure_json` and copied into every view by the grouping scripts (`dict(structure)`).
     If it is missing, return `-1` / `"?"` rather than raising.
   * add the three to `METRIC_FUNCTIONS` (keys `classes_covered`, `classes_total`,
     `missing_classes`) and to `SUMMARY_COLUMNS` (`n_classes_covered`, `n_classes_total`,
     `missing_classes`); follow how `compute_metrics` keys are mapped to summary columns in
     `_build_summary_rows` (the existing `nodes` → `n_nodes` pattern).
   * `render_markdown_report` and `render_console_table`: add a `Classes` column rendered as
     `covered/total`, and a legend line: "**Classes** -- classes with a `Class` node in the graph /
     classes in the dataset. Metrics only cover rows the graph can route to a class it contains."
2. `categorical/run_all_categorical_experiments.py`, `run_one_dataset`: compute the classes present
   from `explanation.nodes` (labels starting with `"Class "`) and return `n_classes_covered` and
   `n_classes_total` (`len(target_names)`) in the result dict. Log them to W&B with the other
   per-dataset values, and add them to the markdown report written by `generate_report`.

## Tests — `tests/categorical/test_metrics_coverage.py`

Import `categorical.run_all_metrics` (check it imports without W&B credentials; it imports `wandb`
lazily in some code paths. If it needs W&B at import time, test only the three functions by
importing them after setting `WANDB_MODE=disabled`). A structure with `target_names` `["a","b","c"]`
and nodes `Class a`, `Class c` → covered 2, total 3, missing `"b"`.

## Validation

1. Tests pass.
2. Apply `compute_metrics` to every view of the baseline (`outputs/categorical_baseline_rev2/`) in a
   scratch script. Acceptance: the covered/total pairs equal the report's BASIC table (#9) for every
   dataset, and are the same for all five views of a dataset (grouping never adds or removes a class
   node).
3. One local pipeline run (`--no-wandb`) of `nursery`: the printed/returned summary contains
   `n_classes_covered = 1`, `n_classes_total = 5`.

W&B tables are refreshed in R1.
