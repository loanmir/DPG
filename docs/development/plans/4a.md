# 4a — Opposite operators: keep `IN (in \ not_in)`

**Problem:** report #4. `cat_grouping_split_conjunction._simplify_same_base`, case 2: when one base
has both `IN` and `NOT IN` clauses, the code keeps whichever set is smaller and drops the other.
The correct result is `base IN (in_set \ not_in_set)`. It goes wrong only on contradictory input
(stress test: 113,440 wrong results in 119 graphs, all from contradictions such as
`Shift IN {Night} AND Shift NOT IN {Night}` → `Shift IN {Night}`), but then a contradiction becomes
a valid rule.
**Approach:** compute the allowed set exactly. If it is empty, keep the base's original clauses
unchanged (contradiction visible), like 3a does for `IN ∩ IN`.
**Depends on:** 3a (same function; 3a already folds the `IN` side by intersection).

## Changes

`categorical/cat_grouping_split_conjunction.py`, `_simplify_same_base`, per-base body after 3a's
`IN` fold. Replace the current case 2:

```python
if in_cats and not_in_cats:
    if len(not_in_cats) < len(in_cats):
        in_cats = []
    else:
        not_in_cats = []
```

with:

```python
if in_cats and not_in_cats:
    excluded = set(not_in_cats)
    allowed = [c for c in in_cats if c not in excluded]
    if not allowed:
        # Contradiction (every allowed value is excluded): keep this
        # base's clauses as they were so it stays visible.
        simplified.extend((base, op, list(cats)) for op, cats in items)
        continue
    in_cats, not_in_cats = allowed, []
```

(`items` is the per-base list of `(op, cats)` in path order that the function already builds; adjust
the names to the code as 3a left it.)

The emission order stays: `NOT IN` clause (if any) before the `IN` clause, bases in first-seen
order.

Docstring of `_simplify_same_base`, case 2: replace "Keep only the tighter (smaller category set);
ties favour ``IN``..." with: the allowed values are `in \ not_in`, emitted as one `IN` clause; the
`NOT IN` clause is then implied and dropped; if nothing is allowed, the clauses are kept as they
were because no row can satisfy them. The example `marital NOT IN {divorced} AND marital IN {married}`
→ `marital IN {married}` stays valid. Remove the sentence "One is implied by the other (the tighter
one), so the looser is dead weight", which is false in general.

`categorical/dpg_equivalence._simplify_against_domains` already computes `in − excluded` correctly.
No change there.
