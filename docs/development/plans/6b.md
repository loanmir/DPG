# 6b — Multi-parent rewrite when every parent gives the same result (optional)

**Problem:** report #6, follow-up. After 6a, a conjunction node with several parents is never
simplified, even when every parent implies the same redundancy (common after cloning: clones carry
the same clauses). The DEDUP view then keeps some cosmetic duplication that the old code removed.
**Approach:** for a child `v` with `k > 1` parents, compute the restricted child for each parent
separately. Rewrite `v` only if all `k` parents are single-clause and produce the **same** new
label, which is then valid on every path into `v`. Never drop a multi-parent node.
**Status:** optional. Run only if 6a's validation shows a noticeable loss of simplification (compare
`n_rewritten` before and after 6a) and the user wants it back.
**Depends on:** 6a.

## Changes

`categorical/cat_duplicate_split_peer.py`:

1. Factor the per-clause restriction loop of `_deduplicate_labels` (the `for clause in child_clauses:`
   block that builds `new_child` and `child_changed`) into a module-level helper:

   ```python
   def _restricted_child(parent: Clause, child_clauses: List[Clause]) -> Tuple[List[Clause], bool]:
       """The child's clauses as they stand on the rows that pass ``parent``,
       and whether anything changed."""
   ```

   Behaviour identical to today's loop (including the "keep `IN {}` contradictions" and "drop
   verbatim duplicates" rules). `_restrict_clause` stays a separate module-level function (the
   harness patches it).
2. Replace 6a's `len(parents[v]) != 1 → continue` with:
   * one parent → as today;
   * several parents → for each parent `p` in `parents[v]`: if `_parsed(p)` is not exactly one
     clause, skip `v`; else compute `_restricted_child(...)`. Apply the rewrite only if every parent
     returned `changed=True` and the **same** formatted label, and that label is non-empty. Never
     take the drop branch for a multi-parent `v`.
   * The edge loop visits `(u, v)` once per parent. Make sure `v` is evaluated once per sweep (for
     example keep a `seen_children` set per sweep).
3. Docstring: describe the consensus rule.

## Tests — add to `tests/categorical/test_dedup.py`

1. Two parents `X NOT IN {a}` and `X NOT IN {a}`-equivalent (same label, different ids, e.g. a node
   and its clone), child `X NOT IN {a, b} AND Y IN {p}` → child rewritten to `X NOT IN {b} AND Y IN {p}`.
2. 6a's test 1 (parents `X NOT IN {a}` and `W > 3.0`) still unchanged.
3. Two parents giving different results (`X NOT IN {a}` and `X NOT IN {b}`) → unchanged.
